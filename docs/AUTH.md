# Authentication requirements

## Confirmed product scope

MooMinds supports sign-up and sign-in with email and password, Google, and Discord. It also supports app-level two-factor authentication using time-based one-time codes (TOTP), such as codes generated by an authenticator app.

All sign-in methods lead to one MooMinds account and the same courses, learning progress, and reminder preferences. A user who enables TOTP must complete the TOTP challenge after the primary sign-in method, including Google or Discord, before receiving a fully authenticated session.

## Implementation requirements

- Email/password: verify ownership of the email address, store only a modern adaptive password hash, provide a time-limited password-reset flow, and limit repeated sign-in attempts. [OWASP password storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) recommends Argon2id where available.
- Google: use [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect), validate the sign-in response and ID token, and identify the external account by the provider's stable subject identifier.
- Discord: use [Discord OAuth2](https://docs.discord.com/developers/topics/oauth2) with the smallest required scopes, such as `identify` and `email` only when an email address is needed. Identify the external account by its Discord user ID.
- Account linking: require an authenticated user action and fresh verification before linking or unlinking another method. Matching email addresses alone must not silently merge accounts.
- TOTP: follow [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238.html). Confirm a valid code during enrollment, protect the shared secret at rest, limit verification attempts, and provide single-use recovery codes. Reauthentication is required to disable or replace the factor. See [OWASP MFA guidance](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html).
- Keep OAuth client secrets, TOTP encryption keys, and related credentials in Vault. Never commit them to a repository or include tokens, passwords, TOTP secrets, or recovery codes in logs.

## Decisions for refinement

- Whether TOTP is optional for all users or required for particular accounts or actions.
- Whether an account may have multiple sign-in methods and how the user adds the first password to a social-login account.
- The exact account-recovery procedure when both the authenticator and recovery codes are lost.
- Session lifetime, device management, and whether to require reauthentication for sensitive account changes.
